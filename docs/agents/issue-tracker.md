# Issue tracker: Spec Kit (local markdown)

Specs, plans and tasks for this repo live as markdown files under `specs/`, managed by
[Spec Kit](https://github.com/github/spec-kit). Project principles live in
`.specify/memory/constitution.md` and are binding.

## Conventions

- One feature per directory: `specs/NNN-<feature-slug>/`, numbered from `001`
- The specification is `specs/NNN-<slug>/spec.md` — WHAT and WHY, no implementation detail
- The technical plan is `specs/NNN-<slug>/plan.md` — HOW
- Tasks are `specs/NNN-<slug>/tasks.md`, generated by `/speckit-tasks`
- Create a feature with `.specify/scripts/bash/create-new-feature.sh --short-name <slug> "<description>"`
  rather than by hand, so numbering and branch naming match the tooling

## When a skill says "publish to the issue tracker"

Add tasks to the feature's `tasks.md`. For work that is not part of a feature, create a
new feature directory using the script above.

## When a skill says "fetch the relevant ticket"

Read the task from `specs/NNN-<slug>/tasks.md`. Always read `spec.md`, `plan.md` and
`.specify/memory/constitution.md` alongside it — a task that contradicts the constitution
must be raised, not silently implemented.

## Wayfinding operations

Used by `/wayfinder`. Exploratory work that is not yet a feature lives under `.scratch/`:

- **Map**: `.scratch/<effort>/map.md` (Notes / Decisions-so-far / Fog)
- **Child ticket**: `.scratch/<effort>/issues/NN-<slug>.md`, numbered from `01`, with a
  `Type:` line (`research`/`prototype`/`grilling`/`task`) and a `Status:` line
  (`claimed`/`resolved`)
- **Blocking**: a `Blocked by: NN, NN` line; unblocked when every listed file is resolved
- **Frontier**: scan for files that are open, unblocked and unclaimed; lowest number wins
- **Claim**: set `Status: claimed` and save before any work
- **Resolve**: append the answer under `## Answer`, set `Status: resolved`, then append a
  context pointer to the map's Decisions-so-far

When an exploration matures into buildable work, promote it to a `specs/NNN-<slug>/`
feature; `.scratch/` is for thinking, `specs/` is for building.
